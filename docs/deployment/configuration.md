# Border-AI Configuration Reference

This document details the configuration system, environment variables, mounted configuration files, and camera ingestion settings for the Border-AI Docker deployment.

---

## 1. Environment Variable Architecture

Border-AI adheres to the 12-factor application methodology:
- **Non-secret configuration** is defined in `.env` (derived from `.env.example`).
- **Cryptographic secrets and credentials** are stored as individual files under `secrets/` and mounted securely via Docker Compose secrets (ADR 0052).
- **Service behavior** is managed through runtime environment variables that point to secret file paths (e.g. `DB_PASSWORD_FILE=/run/secrets/backend_db_password`).

---

## 2. Environment Variables (.env)

The following parameters are configured in the root `.env` file:

### Core Platform Settings
| Variable | Default Value | Description |
|---|---|---|
| `NODE_ENV` | `production` | Node.js execution environment (`production` or `development`) |
| `TZ` | `UTC` | Unified platform timezone across all containers |
| `COMPOSE_PROJECT_NAME` | `border-ai` | Prefix for Docker container names and networks |

### Edge Proxy & Ports
| Variable | Default Value | Description |
|---|---|---|
| `BORDER_HTTP_PORT` | `80` | External HTTP port published by Nginx |
| `BORDER_HTTPS_PORT` | `443` | External HTTPS port published by Nginx |

### Database & Storage Connections
| Variable | Default Value | Description |
|---|---|---|
| `DB_HOST` | `postgres` | Hostname of the PostgreSQL service within `border-data-net` |
| `DB_PORT` | `5432` | Internal database port |
| `DB_NAME` | `border_ai` | Name of the primary PostgreSQL database |
| `DB_USER` | `border_backend` | Database user for backend operations |
| `REDIS_HOST` | `redis` | Hostname of Redis within `border-data-net` |
| `REDIS_PORT` | `6379` | Internal Redis port |
| `REDIS_USER` | `border_backend` | Redis ACL username for backend cache and queues |

### Retention & Purge Policies
| Variable | Default Value | Description |
|---|---|---|
| `RETENTION_EVENTS_DAYS` | `90` | Retention window for general event records and snapshots |
| `RETENTION_ALERTS_DAYS` | `180` | Retention window for alert logs and forensic packages |
| `RETENTION_AUDIT_DAYS` | `365` | Retention window for immutable administrative audit logs |
| `RETENTION_INTERVAL_SECONDS` | `86400` | Execution frequency for the automated retention daemon |

### Media & AI Engine Ingestion
| Variable | Default Value | Description |
|---|---|---|
| `MEDIAMTX_HOST` | `mediamtx` | MediaMTX RTSP relay hostname |
| `MEDIAMTX_RTSP_PORT` | `8554` | MediaMTX RTSP listener port |
| `SIM_CAMERA_COUNT` | `4` | Number of synthetic CCTV streams spawned by simulator |
| `SIM_SCENARIO` | `multi-cam-normal` | Preset scenario for camera simulation (`normal`, `heavy`, `night`) |

## 3. Secret Mount Specifications

Secrets are generated by `scripts/gen_secrets.sh` and read from `/run/secrets/` inside containers:

| Secret Name | Consuming Service | Target Path Inside Container | Purpose |
|---|---|---|---|
| `postgres_admin_password` | `postgres`, `db-init` | `/run/secrets/postgres_admin_password` | Master `postgres` superuser credential |
| `backend_db_password` | `backend`, `db-init` | `/run/secrets/backend_db_password` | Read/write role password for `border_backend` |
| `engine_db_password` | `ai-engine`, `db-init` | `/run/secrets/engine_db_password` | Insert/read role password for `border_engine` |
| `sink_db_password` | `sink`, `db-init` | `/run/secrets/sink_db_password` | Append-only event role for `border_sink` |
| `redis_backend_password` | `backend`, `redis` | `/run/secrets/redis_backend_password` | ACL auth password for backend Redis operations |
| `jwt_private_key` | `backend` | `/run/secrets/jwt_private_key` | Ed25519 PKCS#8 private key for signing auth tokens |
| `jwt_public_key` | `backend`, `ai-engine` | `/run/secrets/jwt_public_key` | Ed25519 SPKI public key for validating JWT signatures |
| `vault_master_key` | `backend` | `/run/secrets/vault_master_key` | AES-256-GCM key for encrypted snapshot archives |

## 4. Camera Ingestion Configuration

Real CCTV RTSP streams or synthetic simulator feeds are configured via `configs/cameras.json` or dynamic API registrations.

### Sample Camera Registration Payload
```json
{
  "camera_id": "cam-gate-01",
  "name": "North Gate Vehicle Ingress",
  "zone_id": "zone-perimeter-north",
  "rtsp_url": "rtsp://mediamtx:8554/cam-gate-01",
  "fps_target": 15,
  "resolution": "1920x1080",
  "enabled_models": {
    "detection": true,
    "tracking": true,
    "anpr": true,
    "face_reid": false
  },
  "zones": [
    {
      "name": "restricted_lane",
      "polygon": [[100, 200], [800, 200], [850, 600], [50, 600]],
      "alert_rules": ["unauthorized_vehicle", "loitering"]
    }
  ]
}
```

Cameras can be updated at runtime without restarting the platform using `PUT /api/v1/cameras/:id`.
